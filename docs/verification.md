# Release verification

The 0.3.0 source was checked on Fedora with Node.js 24.14.0 and system Chrome. **85 Node tests**, **24 existing browser workflow checks** and **12 application-tracker browser checks** passed against recorded source hashes, with no uncaught page or console errors or unrelated failed requests.

The tracker checks capture immutable submitted CV/letter copies, then edit and delete their source documents without changing those copies. They exercise read-only review, PDF/TXT/Word/JSON downloads, independent editable restoration, tasks, due/completion filters, custom text fields, archive/restore, literal search, metadata CSV exports and derived weekly counts. Chromium prints the captured A4 letter after the current document changes to Letter, and an independent PDF inspection checks actual geometry and captured content. The operating-system print dialog is not automated.

A ten-check UI pass covers keyboard controls, desktop, tablet, 390px and 320px layouts. Separate five-check keyboard, five-check resize and five-check mobile gates cover tracker focus retention, filter disappearance fallback, selected-tab visibility without changing page scroll or focus, labelled task controls and a submitted-document modal that fits both phone viewports with 44px action targets. Screenshot review checks the original warm paper identity, readable text and control placement. A text-only enlargement simulation is not native browser zoom or a complete accessibility certification. [Desktop](screenshots/desktop.png) and [mobile](screenshots/mobile.png) captures use synthetic example content.

Optional model writing and persistent sharing passed separate ten-check and eleven-check integrations. Four explicit model requests exercised reviewed summary, tailoring, interview and cancellation flows. The model pass binds unchanged AI code through an exact byte comparison; separate current-source UI and workflow checks cover the final horizontal tab-resize change. Shared documents contain the chosen CV and letter; the private application tracker, submitted attachments and workspace history remain outside the shared-document payload. The static demo provides local workflows; configured services require the Node server.

The [Linux/macOS workflow](https://github.com/tylerbuilds/clearcv/actions/workflows/verify.yml) runs the current commit's Node tests, production build, real Chromium browser smoke and static-server checks on Ubuntu and macOS. GitHub Pages publication requires both platform jobs to pass. Its exact commit run status is the authority for remote qualification; local checks do not substitute for a macOS run. These are browser apps, with no native installer.

[All-tier feature comparison](research/feature-comparison.md) records delivered workflows, explicit gaps, primary sources and sanitised proof metadata. Original authenticated target behaviour and proprietary algorithm equivalence remain unverified. No full commercial feature parity is claimed.
